MASTER PROMPT — OFFLINE INVENTORY TAB MANAGER

Build a complete production-ready offline-first Inventory Management web application.

IMPORTANT:
This must be implemented as a client-side application using:

- HTML5
- CSS3
- Vanilla JavaScript
- IndexedDB
- SheetJS for XLSX import/export if needed

Do NOT use:
- React
- Angular
- Vue
- Node.js runtime
- .NET
- PHP
- Python backend
- SQL database
- Firebase
- Supabase
- REST API
- Authentication server
- Any backend server

The application must work fully offline after the application assets are loaded.

The application should be mobile-friendly and desktop-friendly.

==================================================
1. CORE CONCEPT
==================================================

The application is an Inventory/Product tab based transaction manager.

The reference UI contains multiple product tabs such as:

- Drinking Water
- Biscuit Horli Plus Wel Food
- Biscuit Oval Wel Food
- Biscuit Pistachio Wel Food
- Munchy Luxas

Each product/tab contains its own transaction table.

Every newly created product must automatically create a new independent sheet/tab with the following columns:

1. Date
2. Buyer
3. Spent
4. Remarks

Example:

Date        Buyer              Spent      Remarks
1/2/2026    Nizam Sir Room       2        1 Gust 1 Our Side
2/2/2026    GAP Buyer           12        1 Gust 2 Marchent
2/2/2026    Korean              10        3 Gust 1 Our Side
2/2/2026    Marubini Buyer      19        5 Buyer 7 Our Top Head

The exact column names should be:

Date
Buyer
Spent
Remarks

==================================================
2. PRODUCT/TAB MANAGEMENT
==================================================

Provide a clear "Add Product" button.

When the user clicks Add Product:

1. Ask for Product Name.
2. Validate that it is not empty.
3. Prevent duplicate product names.
4. Create a unique product ID.
5. Create a new product tab.
6. Create an empty transaction collection for that product.
7. Immediately display the new tab.
8. The new tab must automatically contain the standard columns:

Date | Buyer | Spent | Remarks

Allow:

- Add Product
- Rename Product
- Delete Product
- Switch between products
- Search products if the number of tabs becomes large

Before deleting a product, require confirmation.

Deleting a product must clearly warn that all transactions belonging to that product will be deleted.

==================================================
3. TRANSACTION MANAGEMENT
==================================================

Inside every product tab provide:

- Add Transaction
- Edit Transaction
- Delete Transaction

Transaction fields:

Date
Buyer
Spent
Remarks

Date should use a proper date input.

Spent must be numeric.

Buyer and Remarks are text.

Support keyboard-friendly desktop input and touch-friendly mobile input.

Allow sorting by date.

Allow newest/oldest date ordering.

Show total Spent for the currently selected product.

Example:

Total Spent: 1,245

==================================================
4. DATA STORAGE
==================================================

Use IndexedDB as the primary persistent local database.

Do NOT use localStorage as the primary database.

Database structure should be logically separated into:

Products
Transactions

Each transaction must reference its product using productId.

Example transaction:

{
    id,
    productId,
    date,
    buyer,
    spent,
    remarks,
    createdAt,
    updatedAt
}

Data must persist after:

- browser refresh
- browser restart
- device restart

The application must work without internet after the initial assets are available.

==================================================

Create a dedicated "Reports" or "Custom View" section.

The user must be able to select:

A. All Products

OR

B. One or more selected Products

OR

C. One specific Product

From Date

[Drinking Water]

Date
Buyer

Grand Total Spent

Allow filtering by:

- Product
- Date range
- Buyer text search

==================================================
6. EXPORT
==================================================

Implement professional XLSX export.

Use SheetJS.

The user must have the following export options:

A. Export Current Product

Export the currently selected product into an XLSX file.

Example filename:

Biscuit_Oval.xlsx

B. Export Selected Products

If multiple products are selected, create one XLSX workbook.

Each selected product should become a separate worksheet.

C. Export All Products

Create one XLSX workbook containing every product as a separate worksheet.

D. Export Current Filtered Report

Export only the transactions currently visible after applying:

- product selection
- date range
- buyer search

The generated workbook must contain clean headers:

Date
Buyer
Spent
Remarks

Add a total row where appropriate.

Do not export unnecessary UI fields.

==================================================
8. BACKUP AND RESTORE
==================================================

Because this is an offline IndexedDB application, implement complete backup/restore.

Provide:

Backup Data
Restore Data

Backup should export all products and transactions into a JSON file.

Example:

inventory-backup-2026-09-23.json

Restore should allow the user to select a JSON backup file and restore the complete application data.

Before restore:

Ask for confirmation.

Provide safe validation so malformed JSON does not corrupt existing data.

Also provide:

Clear All Data

with a strong confirmation dialog.
